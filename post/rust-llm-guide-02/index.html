第 2 课：自动微分 Autograd —— 让模型学会"自我修正"

代码位置：src/tensor.rs（grad / 各运算的反向闭包登记）、src/autograd.rs（线性 tape 与 backward） 演示入口：src/main.rs

1. 本课要搞懂的问题

  1. 什么是梯度？为什么"梯度下降"能让模型学习？
  2. 链式法则是怎么回事？为什么反向传播比正向求导更高效？
  3. 怎么用 Rust 把"求导"自动化，让代码自动算出每个参数的梯度？

2. 从"拟合直线"说起

上一课我们实现了矩阵乘法。现在想象一个最简单的"学习"任务： 已知一些点 (x, y)，它们近似满足 y = 2x + 1，但参数 w、b 未知。怎么让程序自己找到 w=2、b=1？

思路：先随便给个初始值（比如 w=0, b=0），然后：

  1. 算出预测值和真实值的差距 → 损失 loss
  2. 问：如果我调大一点 w，loss 会变大还是变小？ → 这个方向就叫梯度
  3. 沿着"让 loss 变小的方向"微调 w、b
  4. 重复直到 loss 足够小

第 2 步里的"损失随参数的变化率"，数学上叫偏导数。所有参数偏导数的集合叫梯度。

3. 梯度下降公式

对参数 θ，更新规则只有一行：

θ = θ - 学习率 × ∂loss/∂θ
  • ∂loss/∂θ > 0：θ 增大 loss 也增大 → 所以减去它，θ 变小
  • ∂loss/∂θ < 0：θ 增大 loss 减小 → 减去它，θ 变大
  • 学习率（learning rate）控制每次迈多大步子，太小太慢、太大震荡

我们采用的损失是 MSE（均方误差）：

loss = Σ (pred - y)²        # pred = x·w + b

4. 链式法则：复合函数求导的关键

问题来了：loss 是复合函数，loss = g(pred)，而 pred = f(w)。 要求 ∂loss/∂w，不能直接求，需要一层层拆开：

链式法则：如果 z = g(f(x))，那么

dz/dx = (dg/df) × (df/dx)

类比"流水线"：损失一路流经 pred 再到 w，每一段的"变化率"相乘就是总的"变化率"。

例：z = x*y + w，各梯度是：

∂z/∂x = y      （对 x 求导时把 y 当常数）
∂z/∂y = x      （对 y 求导时把 x 当常数）
∂z/∂w = 1      （加法求导是 1）

程序输出正是 dz/dx=3, dz/dy=2, dz/dw=1 ✓

5. 反向传播：把链式法则批量自动化

手工对每个参数求导太累，模型参数动辄百万个。怎么办？

核心思想：前向传播时，把每一步运算记录下来，形成一张计算图；反向传播时，从 loss 出发，把梯度沿图逐层往回传，每层的梯度都复用上一层的结果。

前向（边算边记）：  x ──┐
                     mul ──► t ──┐
                     y ──┘         add ──► z = 7
                     w ───────────┘

反向（梯度倒流）：  x ◄── grad=3
                     t ◄── grad=1 ──► w ◄── grad=1
                     y ◄── grad=2

关键好处：每个中间结果只算一次梯度，总计算量与前向相当，而不是对每个参数各算一次前向（那样要 O(参数个数) 倍计算）。这就是反向传播比"数值微分"快的原因。

6. Rust 实现：线性 tape 登记反向

张量只保留数据本体，计算图结构不在张量上——反向闭包统一登记到线性 tape（thread_local! 线程局部存储，每条训练线程各持一条，加锁无竞争）：

pub struct Tensor {
    data: Shared<Buffer>,           // 数值（Shared = Arc<Mutex>；Buffer::F32 / Bf16 存储层）
    shape: Vec<usize>,
    strides: Vec<usize>,            // 视图步长，permute 零拷贝（见第 5 课）
    grad: Shared<Vec<f32>>,         // 梯度，恒 f32，初始全 0，反向时累加
    requires_grad: Arc<AtomicBool>, // 是否需要梯度（参数=true，数据=false；Relaxed 原子读写）
    // 计算图结构不在这里：反向闭包登记到 autograd 的线性 tape
}

// autograd.rs：一条 tape 记录
struct TapeEntry {
    out: usize,        // 输出张量的身份键（grad 缓冲地址）
    parents: Vec<usize>, // 各父张量的身份键
    f: BackwardFn,     // 链式法则闭包 Arc<dyn Fn()>
    done: bool,        // 本次 backward 是否已执行
}
thread_local! { static TAPE: RefCell<Vec<TapeEntry>>; } // 线程局部线性 tape，按前向顺序追加

每个"需要梯度"的算子前向算完后，调用统一登记门 record(&输出, vec![父们], Arc::new(反向闭包)) 把这一步记到 tape 末尾。

用到的 Rust 核心特性：

  • Arc<T>（原子引用计数）：计算图里一个节点可能被多个运算共享，Arc 让多份句柄指向同一份数据；原子计数线程安全，计算图可以跨线程共享（供 rayon / 数据并行使用）
  • Mutex<T>（互斥锁，经薄封装 Shared<T> 暴露）：让"共享数据"同时可以"可变借用"，Shared::borrow()/borrow_mut() 返回 MutexGuard，用运行期加锁取代 RefCell 的运行期借用检查
  • 每定义一个运算，就写两个东西：前向（算结果）+ 反向闭包（算梯度传给输入），并 record 登记
  • 身份键去重：Shared::as_ptr(&t.grad)（梯度缓冲地址）唯一标识一个节点，tape 靠它回溯可达性
  • 守约：反向闭包内不得构造 Tensor——backward 扫描期间 tape 已被 borrow_mut，闭包内再 record 是 RefCell 运行期 borrow panic（全库接线点已核查）

7. 各运算的反向规则（背下这几条）

前向 反向（g 是输出的梯度）
c = a + b ∂a += g，∂b += g
c = a - b ∂a += g，∂b -= g
c = a * b ∂a += g*b，∂b += g*a
c = a * s ∂a += g*s
c = a @ b ∂a += g @ bᵀ，∂b += aᵀ @ g
c = sum(a) ∂a += g（每个元素都加同一个 g）

以乘法为例，真实的 mul 只有一行（src/tensor.rs 的 Tensor::mul）：前向是 a * b，反向返回 (∂c/∂a, ∂c/∂b) = (b, a)，形状检查、广播、并行和建图都交给通用函数 binary：

pub fn mul(&self, other: &Tensor) -> Tensor {
    // ∂c/∂a = b，∂c/∂b = a
    self.binary(other, |a, b| a * b, |a, b| (b, a))
}

下面是 binary 内部反向逻辑的原理示意（省略广播与并行细节；真实实现见 src/tensor.rs 的 binary）。注意累加 +=，因为一个张量可能被多条路径使用，梯度要累加：

// 原理示意
let g = rg.borrow();
let mut sgm = sg.borrow_mut();
let mut ogm = og.borrow_mut();
for i in 0..g.len() {
    sgm[i] += g[i] * od_b[i];    // ∂a = g * b
    ogm[i] += g[i] * sd_b[i];    // ∂b = g * a
}

8. 反向传播主流程：逆序扫描线性 tape

图是有向无环图（DAG），必须保证"子节点先算，父节点后算"（拓扑逆序）。 线性 tape 的妙处：tape 按前向顺序追加 ⇒ 逆序扫描就是拓扑逆序——子节点总是比父节点登记得晚，所以一趟从尾到头的扫描就是合法的反向执行序，不需要显式做拓扑排序：

pub fn backward(&self) {
    // 1. loss 自己的梯度 = 1（d loss / d loss = 1）
    self.grad.borrow_mut()[0] = 1.0;
    // 2. 锁 tape，从末尾逆序扫描（逆序 == 拓扑逆序）
    let mut reachable = HashSet::new();
    reachable.insert(身份键(self));   // 从根出发的可达集
    for i in (0..tape.len()).rev() {
        if reachable.contains(&tape[i].out) {
            (tape[i].f)();                        // 执行链式法则闭包
            reachable.extend(tape[i].parents);    // 沿父键继续回溯
            tape[i].done = true;
        }
    }
    // 3. 只移除本次执行的条目；回溯不到根的（其它交错前向的图、故意不反的分支）保留
    tape.retain(|e| !e.done);
}

要点：

  • 可达集裁剪：只有能沿"输出 → 父"身份键回溯到 loss 的条目才执行。不能简单"执行到根条目就截断"——流水线调度（第 9 课 1F1B）会让多个 micro-batch 的前向在 tape 上交错且反向非 FIFO，按位置截断会误杀别的图
  • 选择性移除：执行过的条目移除，使 tape 每步稳态有界；aux_only_balance 这类只反部分图的 demo，另一部分永远不可达，用 clear_tape() 整条清掉
  • 用 Shared::as_ptr(&t.grad) 作为节点的唯一身份键（一个节点被多个运算共享时靠它命中同一条回溯路径）

9. 训练循环：四步舞

一次"学习"包含四步（也是所有深度学习框架训练循环的骨架）：

// 1. 前向：算预测和损失
let loss = x.matmul(&w).sub(&y).mul(...).sum();
// 2. 反向：自动算每个参数的梯度
loss.backward();
// 3. 更新：w -= lr * 梯度（这里手动实现，展示底层）
w.set_data(vec![w.data()[0] - lr * w.grad()[0], ...]);
// 4. 清零梯度：否则下一轮会把旧梯度累加上去
w.zero_grad();

这段线性回归在仓库里以单元测试的形式保留：cargo test test_linear_regression_converges （数据是 y = 2x + 1，用均值 MSE + lr = 0.005 跑 5000 步，断言 w→2.0、b→1.0，容差 0.1）。 demo 子命令里没有这一段——它依次跑的是 XOR MLP、BPE 分词、小 Transformer 训练与生成。

10. 一个重要的细节：梯度累加

为什么用 += 而不是 =？因为一个张量可能被多条路径使用。

例：z = x*x。求梯度时 x 有两条路径（z 对第一个 x 的导数是第二个 x，对第二个 x 的导数是第一个 x），必须相加：∂x = g*x + g*x = 2gx。

代码里我们用 Shared::ptr_eq(&sg, &og) 判断两个父节点是不是同一个张量，是的话就合并累加。这也是测试 test_chain_rule 验证的内容。

11. 运行与验证

cargo test     # 测试全部通过（本课内容对应 test_chain_rule / test_linear_regression_converges）
cargo run --release -- demo    # 项目演示入口：XOR MLP → BPE 分词 → 小 Transformer 训练与生成

12. 小结与下一课

本课小结

  • 梯度 = 损失对参数的"变化方向"，梯度下降就是沿着反方向走
  • 链式法则 + 计算图 = 反向传播，一次性高效算出所有梯度
  • Rust 用 Arc<Mutex>（Shared 封装）+ 闭包实现了可自动求导的张量
  • 亲手跑通了第一个"会学习"的程序：线性回归（test_linear_regression_converges）

拓展方向

核心内容已全部实现，这里是进阶拓展。

  1. 给张量加一个 pow(n) 运算（c = a^n），推导并实现它的反向传播（提示：∂a = g * n * a^(n-1)）。
  2. 思考：为什么 loss 必须是标量（0 维）才能调用 backward()？如果不是标量会怎样？
  3. 把学习率从 0.001 改成 1.0，观察 loss 曲线，解释发生了什么（振荡/发散）。
  4. 这是本项目的"心脏"。试着不看代码，自己画出 loss = (x·w - y)² 的计算图并手算 ∂loss/∂w。
