第 48 课：FP4 量化感知训练 —— E2M1 与 4 位权重

本课已落地为可运行代码：src/fp4.rs（E2M1 编解码 + nibble 打包的 Fp4Tensor + roundtrip_params_in_place），接入 src/train.rs 的训练步， 演示命令 src/cmd/experiments.rs 的 cmd_fp4。 配置开关：train.fp4（默认 false）/ 命令 cargo run -- fp4。

与第 43 课的关系：第 43 课把权重压到 8 位（E4M3 + 每 32 元素一个 scale = 9 bit/元素）。 本课再砍一半，只留 4 位（E2M1 + 每 32 元素一个 scale = 5 bit/元素，对 f32 是 6.4 倍压缩）， 代价全在精度上。两课的账本必须并排看才有意义。

1. 本课要搞懂的问题

  1. 4 位里塞下"符号 + 指数 + 尾数"之后，一个数还剩多少精度？
  2. E2M1 为什么既没有 Inf 也没有 NaN？没有 NaN 码时 NaN 输入怎么办？
  3. 为什么 FP4 离开分块 scale 就几乎不可用？
  4. 5 bit/元素这个数字是怎么算出来的？"块大小 1"为什么反而比 f32 更费？
  5. 权重掉到 FP4 之后，验证 loss 会差多少？（这是本课的账本）

2. E2M1：4 位能表示的全部 16 个数

字段切分是 1 位符号 + 2 位指数 + 1 位尾数，指数偏置取 1，于是 value = (1 + m/2) · 2^(ef − 1)。正号侧只有 8 个值：

码 ef m 解码值 与上一档的相对间距
0x0 0（非规格化） 0 0 —
0x1 0 1 0.5 —（上一档是 0，无定义）
0x2 1 0 1.0 100%
0x3 1 1 1.5 50%
0x4 2 0 2.0 33%
0x5 2 1 3.0 50%
0x6 3 0 4.0 33%
0x7 3 1 6.0 50%

加上符号位，16 个码全是有限值——E2M1 没有 Inf 码、也没有 NaN 码 （对比 E4M3 至少留了 0x7F 当 NaN）。这条推论很硬：

  • |x| > 6 → 在编码前就饱和到 ±6.0；
  • NaN → 4 位里无处可放，也只能饱和到 ±6.0；
  • 因此 encode_e2m1 里没有任何"特殊码"分支，只有饱和。

精度直觉：在正规数区间（≥ 1.0）内，最差相对间距出现在 [4,6] 段，是 2/4 = 50% （间距一律按「相邻间距 ÷ 上一档」算，fp4 命令第一节的表就是这个口径）；由此得单元素相对精度上界 2^−(mb+1) = 0.25。而 E4M3 的尾数有 3 位，同一口径是 2⁻⁴ ≈ 6%。差了一个数量级。

3. 分块缩放：FP4 的必需品

正因为单个数太糙，FP4 必须靠 分块 scale（MXFP4：每 32 个元素共享一个 f32 scale） 把小尺度的块整体抬进 [0, 6]：

scale = max|x_block| / 6.0
q     = encode_e2m1(x / scale)      // 半个字节（nibble）
x'    = decode_e2m1(q) * scale

3.1 位宽账本

FP4 + 每 32 元素一个 scale：4 bit/元素 + 32/32 bit/元素 = 5 bit/元素 → 32/5 = 6.4 倍
FP8 + 每 32 元素一个 scale：8 bit/元素 + 32/32 bit/元素 = 9 bit/元素 → 32/9 ≈ 3.56 倍

收益与开销必须一起看——cargo run -- fp4 第二节特意把"块大小 1"也列出来：

每 1 个元素一个 f32 scale：4 bit + 32 bit = 36 bit/元素 —— 比 f32 还费 12.5%

那不是量化，只是把 f32 换了个地方存。量化最容易自欺的地方就在这里。

3.2 为什么 bits_per_element 要算得这么细

Fp4Tensor::bytes 报的是真实字节数：码按 nibble 打包 （元素 i 占字节 i/2 的低/高半字节），长度 ceil(n/2)。如果偷懒每元素存一个 u8， 压缩比会被虚报一倍——账本就成了自欺的第二个入口。

位置 内容

src/train.rs 训练步第 7c 步：opt.step() 之后、下次前向之前把二维权重往返量化回写
src/cmd/experiments.rs cmd_fp4 fp4 子命令：16 个码 → 分块账本 → f32/FP8/FP4 验证 CE 三方对照

为什么只量化权重：与第 43 课同理——真实低精度训练把 1 维的 norm 增益 / bias 留在高精度 （它们的尺度与矩阵权重差好几个数量级，压到 4 位会直接把归一化打歪）。

默认路径逐位不变

  • 默认 fp4 = false：训练步第 7c 步整段不执行，参数、随机数消耗、前向都与加本课之前逐位一致；
  • 单测 test_fp4_changes_training_same_seed 里同时断言了 TrainConfig::default().fp4 == false；
  • FP4 的编解码是纯函数，不参与计算图、不影响反向——梯度与优化器状态始终是 f32 （这正是"量化感知训练"里"感知"二字的含义：让优化器看见量化后的权重）。

5.1 实测账本（cargo run --release -- fp4，默认参数）

权重矩阵 [256×256]，行尺度从 ~1.0 一路递减到 ~1e-6（模拟真实权重不同通道的量级差）：

块大小 SNR(dB) 平均绝对误差 最大绝对误差 占用（f32 的 %） bit/元素
整张 11.1 2.360e-2 4.275e-1 12.5% 4.00
128 19.3 6.221e-3 4.477e-1 13.3% 4.25
32 19.9 5.592e-3 4.348e-1 15.6% 5.00
1 151.9 5.412e-10 2.384e-7 112.5% 36.00
fp8/32（对照） 32.5 1.200e-3 9.497e-2 28.1% 9.00

两处值得盯住：

  • 块大小 1 的 SNR 高到 151.9 dB，但占用 112.5% —— 比 f32 还费。 它是"用显存换精度"的极端， 不该叫量化；把它列出来就是为了防止只看 SNR 自欺。
  • 同一块大小下 FP8 的 SNR（32.5）比 FP4（19.9）高 12.6 dB，这就是少一半位宽的标价。

同一个 60064 参数的小模型（n_embd=32、n_layer=2，训练 300 步后交叉熵 3.6363 → 0.7696、 困惑度 37.95 → 2.16），验证集上只改权重的存储精度：

权重要求 验证 CE 困惑度 相对变化 bit/元素 压缩比
f32（原始） 2.8526 17.333 — 32.00 1.00x
fp8/e4m3/32 2.8546 17.368 +0.07% 9.00 3.56x
fp4/e2m1/32 2.8698 17.634 +0.60% 5.00 6.40x

读法：位宽从 9 再砍到 5（显存又省 1.8 倍），CE 劣化从 +0.07% 涨到 +0.60%，约 8.6 倍。 权重掉到 FP4 仍只让 CE 涨零点几个百分点，"FP4 更适合权重"这个工程结论在本仓库的小模型上同样成立； 但再说一遍——这里没有 FP4 kernel，一个字节的显存、一次乘加的速度都没省下，它不是性能数据。

常见坑（实测踩出来的）

1. "ties-to-even 取偶数档"要看清是谁的偶数

第一版把 0.75（0.5 与 1.0 的中点）当成"取偶数档 0.5"，断言写成码 0x1，实测失败。 正确结果是 1.0（码 0x2）：ties-to-even 比的是尾数字段的最低位， 而非规格化的 0.5 存的是 m = 1（奇），1.0 作为最小正规数存的是 m = 0（偶）， 所以往 1.0 靠。实现上这正好落在"把 ax/step 取整再判奇偶"这条路径上 （ax/step = 1.5 → 2，2 是偶数），不需要额外特判。

顺带一个容易踩的点：非规格化与正规数的交界处没有断点——ax/step 舍入到 2^mb 时 得到的码恰好是最小正规数（ef = 1, m = 0），所以解码分支里不需要为交界写特例。

2. 别把"4 位"直接理解成"省 8 倍显存"

32 / 5 = 6.4 才是真实压缩比，因为每个 block 还要摊 1 bit 的 scale。而 FP8 是 32 / 9 ≈ 3.56。 换句话说：从 bf16 走到 FP8 省下的显存，比从 FP8 走到 FP4 还多——位宽越小， 固定开销（scale）摊得越薄，边际收益越低。这还没算上真实硬件里 FP4 通常要求 更规整的 block 布局（MXFP4 的 block 是 32，不能随便改）。

6. 小结与下一课

本课小结

FP4 在 E2M1 + 每 32 元素一个 scale 下是 5 bit/元素（对 f32 6.4 倍压缩），权重掉到 4 位只让验证 CE 涨 +0.60%；同样地，这里没有 FP4 kernel，省下的是纸面账本。

拓展方向

  • block 大小扫描：32 / 16 / 8 的 SNR × 位宽曲线，找"固定开销 vs 局部适配"的拐点。
  • 误差反馈（error feedback）：把每次舍入的残差 x − x' 累加回下一步的参数， 这是 QAT 之外的另一种"补偿量化误差"的做法，实现量很小（一个与参数同形的 buffer）。
  • 梯度也落 FP4：本课只压权重。把激活 / 梯度也压到 4 位会明显更疼，可以先用 Fp4Tensor::quantize 在中间激活上量一遍误差再决定。
  • 真 kernel：本仓库没有 FP4 的 tensor core 路径，所有收益都是纸面上的（口径见本课「5.1 实测账本」的"读法"段：这里没有 FP4 kernel，它不是性能数据）。
