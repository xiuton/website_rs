从零用 Rust 实现大语言模型 —— 学习计划

目标：不使用任何深度学习框架（如 tch-rs / candle / burn），仅用 Rust 标准库， 从零手写张量、自动微分、神经网络层、Transformer 架构，最终训练出一个能生成文本的可用 Transformer 模型。

核心理念：每一步都亲自动手实现，每一步都配套教程文档。 每节课的文档都在 docs/ 目录下，代码在 src/ 目录下，一一对应。

最终成果：一个真实可用的 LLM 训练与推理框架，支持训练、评估、生成、对话、监督微调（SFT）、微调、Beam Search、GPU 加速等完整功能。

为什么从零写？

  • 学习张量/自动微分/反向传播，才能真正理解 PyTorch 等框架背后的原理。
  • 理解每一个数学公式如何变成一行行代码。
  • 训练过程透明可控，随时可以打印中间结果检查正确性。

依赖策略

  • 原则上零依赖：所有张量、数学运算、自动微分、网络层全部自己写。
  • 允许极少量工具库，使用时会明确说明并解释其作用（例如 serde_json 做配置序列化、clap 做命令行、rayon 做 CPU 并行、tiny_http 起 HTTP 服务、可选的 wgpu 做 GPU 加速）。
  • 每新增一个依赖都必须有理由，不能"图省事"。

总体路线图（12 个阶段，50 课）

推荐阅读顺序：按下方阶段顺序阅读，每个阶段内的课程按编号顺序。 阶段六（训练进阶与正则化）和阶段七（现代 LLM 架构）可以灵活安排——先学 Dropout 等正则化技巧，再学 RoPE / RMSNorm 等现代组件，或反过来。

阶段十二：训练进阶与低精度（第 42~50 课）

本阶段补上"用更少的监督、更少的比特训练模型"以及"更聪明的优化与架构微调"这几件事： 蒸馏把大模型的知识搬给小模型，FP8 / FP4 把数值精度一路压到 8 位、4 位浮点，WSD 换掉 cosine 的调度曲线， QK-Norm 钉死注意力 Q/K 的尺度，Muon 把更新矩阵正交化，mHC 把残差流拓宽成多条并用双随机矩阵约束混合， CSA + HCA 把长序列注意力在序列维压缩后只对少数块做稀疏打分， MLA 解耦 RoPE 把位置信息从压缩 latent 里摘出来，从而解锁 W_UK/W_UV 权重吸收。 各课都配有可运行实验与数值自检 （梯度有限差分 / 标准码值对照 / Newton–Schulz 闭式核对 / 双随机投影不变量 / 覆盖不变式 / 吸收数值等价）。 下表括号里的『N 个单测』同样是写作时的快照，会随代码增长而漂移；以 cargo test <关键词> 的实际输出为准。

具体学习方法：

  1. 先读每课的教程文档（docs/XX-xxx.md），理解原理。
  2. 再看对应源码（src/），对照实现。
  3. 自己动手改代码、跑实验，验证理解。
  4. 读完每课末尾的「拓展方向」（核心内容已全部实现，那里是进阶拓展）。

每个阶段会学到的核心数学/ML 概念

  • 线性代数：矩阵乘法、转置、点积、低秩分解（第 1、5、29 课；MLA 的 KV 低秩压缩在第 23 课延伸，解耦 RoPE 与权重吸收在第 50 课）、正交化（第 46 课 Muon 的 Newton–Schulz 迭代）
  • 微积分：偏导数、链式法则、梯度（第 2 课）
  • 概率：softmax、交叉熵、采样、拒绝采样（第 6、15、34 课）
  • 信息论：KL 散度、温度缩放、dark knowledge（第 42 课知识蒸馏）
  • 数值表示：浮点位结构与动态范围、E4M3/E5M2、E2M1、分块缩放 micro-scaling（第 43、48 课 FP8 / FP4）
  • 优化：梯度下降、学习率、动量、AdamW（第 6、7、17 课）、学习率调度曲线（cosine / WSD，第 18、44 课）、Muon 的正交化更新（第 46 课）
  • 深度学习：反向传播、正则化、归一化、Dropout（第 2、5、11、19 课；QK-Norm 是 RMSNorm 用在注意力 Q/K 上的变体，第 45 课）、多条并行残差流与双随机混合矩阵（第 47 课 mHC）、序列维块均值压缩与稀疏 / 分层注意力（第 49 课 CSA + HCA）、解耦 RoPE 与线性注意力吸收（第 50 课 MLA）
  • NLP：分词、词嵌入、注意力、Transformer（第 8-12 课）
  • 信息检索：向量相似度、近似最近邻搜索（第 37 课）
  • 强化学习：策略梯度、PPO、奖励建模、DPO（第 36 课）
  • 系统工程：并行计算、通信原语、显存优化（第 38 课）

验收标准

  • 每一课结束，cargo run --release -- demo（或对应子命令）能正常运行并输出预期结果。
  • 每一课都有配套文档，说明原理 + 代码讲解 + 练习。
  • 第 7 课结束时，我们的 MLP 能在 XOR 任务上收敛（验证自动微分正确）。
  • 第 16 课结束时，模型能生成通顺的短文本。
  • 第 30 课结束时，掌握所有现代 LLM 的核心组件（GQA、Flash Attention、LoRA、AMP 等）。
  • 第 38 课结束时，理解从预训练到对齐、从单卡到分布式的完整 LLM 技术栈。
  • 第 39 课结束时，项目具备完整的工程化能力：
    • 23 个 CLI 子命令（本课落地 9 个：train / eval / generate / chat / sft / finetune / preset / demo / bench； 后续各课陆续接入 serve / scaling / moe / quant / distributed / align / rag / speculative / distill / fp8 / fp4 / csa / mla， 以及没有对应课、专做权重导入的 import-hf；完整清单见 docs/39 §2.1）
    • HuggingFace 权重导入：import-hf 把 config.json + *.safetensors 一次转成本仓库原生 LLMCP2 （权重 only 档），并把 rope_style / bias 开关 / 输出头是否绑定等语义一并写进存档头
    • 分词器可持久化保存和加载（训练一次，多次使用），也可直接导入 HuggingFace 的 tokenizer.json
    • 预设配置（small / medium / large）一键生成
    • 监督微调（SFT）：用「提问→回答」语料把只会续写的预训练模型教会应答（带 loss 掩码，输出到 {out_dir}-sft）
    • 微调工作流（加载预训练模型 → 继续训练）：sft 全参更新；finetune 走 LoRA——冻结主干、只训每层 Q/K/V 的低秩适配层（本项目实测可训练参数 1.32%）
    • 交互式对话模式（持续输入，模型实时回复）
    • Beam Search 生成（通过 generate --beam 命令行参数直接使用）
    • 多文件数据加载（支持目录路径，自动合并 .txt 文件）
    • 训练指标 CSV 日志（loss / lr / ppl / tokens_per_sec）
    • checkpoint 为二进制 LLMCP2 且原子写入（先写 <path>.tmp 再 rename），训练中断不会毁掉上一份完好存档
  • 第 40 课结束时，模型能像主流大模型 API 一样被调用：
    • serve 子命令起一个 OpenAI 兼容服务，POST /v1/chat/completions 非流式与 SSE 流式都能返回
    • 任意 OpenAI 兼容客户端把 base_url 指到本服务即可对话（另有 GET /v1/models、GET /v1/embeddings）
    • --api-key 鉴权、CORS 预检、请求日志、/v1/status 队列状态可查
    • GET /openapi.json /openapi.yaml 输出 OpenAI 风格的 OpenAPI 3.1 规范，请求体自带能跑通的 example、导入 Postman / Apifox 点 Send 即用（鉴权在 collection 填一次即可）；serve 启动时自动把静态版写进 openapi/（删了会重建）
    • 客户端断开连接时生成立即中止，不空烧算力
    • serve 默认顺带启动 web/ 前端测试页（vite + React + TS，http://localhost:5173），可视化调流式对话 / embeddings / 状态接口，代理同源转发免 --cors（--no-web 关闭）
  • 第 41 课结束时，模型具备最基础的多模态能力：
    • 图片理解：generate --image 把图经 ViT 注入占位符，模型围绕它生成文字
    • 图片生成：vlm_file 图文训练 + vq_steps 预训练 VQ-VAE，采出完整图片段后解码为 gen_image_{i}.png
    • serve 非流式回包内嵌 message.image_url（data URI），OpenAPI 规范同步声明
    • serve 图片理解：末条 user 消息带 message.image_url（data URI / 裸 base64）即传图，服务端解码注入 ViT；流式在 finish 前发一帧 delta.image_url 出图
    • web 测试页 📎 上传输入图、气泡内渲染生成图
    • 不配 model.vision / train.vlm_file 时，行为与纯文本版本逐位一致
  • 第 42 课结束时，理解并用上了知识蒸馏：
    • cargo run --release -- distill 跑完三节：软标签熵随温度的变化、KD 梯度有限差分核对 （最大误差 ~1e-4 量级）、「软标签 vs 硬标签」同学生同数据对照
    • 明白 T² 为什么不能省、为什么 teacher 与学生必须共用分词器
  • 第 43 课结束时，理解 FP8 并量出它的数值代价：
    • cargo run --release -- fp8 跑完三节：E4M3/E5M2 标准码值对照、分块缩放的误差/开销权衡、 权重落 FP8 后的 loss 变化
    • 清楚它的边界：本仓库是纯数值模拟，不带来任何加速；真实收益来自 GPU FP8 tensor core
    • train.fp8 打开后每步把二维权重按 E4M3 + 每 32 元素一 scale 往返量化，梯度与优化器状态仍是 f32
  • 第 44 课结束时，理解并会用 WSD 调度：
    • train.lr_schedule = "wsd" + wsd_decay_frac 后曲线呈三段式（warmup 线性上升 → 稳定段恒为 max_lr → 末段线性退火到 min_lr）
    • 明白"稳定段任意时刻都能切出退火"为什么让总步数不必前置；默认 "cosine" 与加 WSD 之前逐位相同
  • 第 45 课结束时，明白 QK-Norm 解决什么问题：
    • model.qk_norm = true 后每个头的 head_dim 向量 RMS = 1（投影之后、RoPE 之前），对输入整体缩放不变
    • 清楚它的代价：每层多 2 × head_dim 参数，且会让 GPU 常驻快路失效、退回逐算子路径
  • 第 46 课结束时，能用 Muon 跑通训练并且知道坑在哪：
    • train.optimizer = "muon" 后二维权重走 Newton–Schulz 正交化、一维参数自动回退 AdamW
    • 记住"沿用 AdamW 的学习率 Muon 会几乎不动"——每元素更新量约 lr/√cols，峰值学习率要放大 √cols 倍
    • Muon 的状态能进 checkpoint 续训（state / restore_state 往返一致）
  • 第 47 课结束时，理解 mHC 并把残差流真正拓宽过：
    • model.n_stream = 2 后每层多了 hc_attn / hc_mlp 两组门控参数（α / β / A）， 模型入口把一条残差流扩成 2 条、出口用可学 γ 收敛回一条
    • 说得清 双随机矩阵 为什么能同时保证"谱范数为 1（信号不放大）"与"列和为 1（保均值）"， 以及 Sinkhorn–Knopp 迭代为什么能当"投影算子"用还照样能反向
    • 知道两个实测踩过的坑：入口各流雷同会让首层 α/A 拿不到梯度；收敛用均匀平均 会让末层 β/A 变成死参数（所以收敛权重 γ 必须是可学的）
    • 默认 n_stream = 1 不构造任何超连接参数、前向逐位不变
  • 第 48 课结束时，理解 FP4 并把"4 位"的账算清楚：
    • cargo run --release -- fp4 跑完三节：E2M1 全 16 码对照、分块缩放的位宽 / 精度账本、 f32 / FP8 / FP4 三方验证 CE 对照
    • 说得清 E2M1 为什么既没有 Inf 码也没有 NaN 码——|x| > 6 与 NaN 都只能饱和到 ±6.0
    • 算得清 5 bit/元素 = 4 bit 码 + 每 32 元素摊 1 bit scale（对 f32 6.4 倍）， 而 FP8 是 9 bit/元素（3.56 倍）；别把"4 位"直接当成"省 8 倍"
    • train.fp4 打开后每步把二维权重按 E2M1 + 每 32 元素一个 scale 往返量化回写， 梯度与优化器状态仍是 f32；与 train.fp8 同开时以 FP4 为准
  • 第 49 课结束时，理解 CSA + HCA 混合注意力并把长序列的账算清楚：
    • cargo run --release -- csa 跑完三节：三分支覆盖不变式、KV 字节账本、top-k 稀疏算力账本
    • 说得清三层各自管什么——局部窗口给"最近的 m 个位置"全分辨率，细压缩（CSA）给 "已完成块"的块均值 + top-k 稀疏，粗压缩（HCA）再平均一遍给出廉价的全局覆盖
    • 记得住那条唯一的因果判据：压缩块只有在块末位置 ≤ i 时才可见（B_i = floor((i+1)/m)）； 用"块起点 ≤ i"会让块内尚未生成的 token 漏进来，loss 会虚假变好
    • 算得清两组账：KV 字节 2·(m + T/m)·n_kv·hd·4（存储口径，m ≈ √T 附近最省）， 与每 query 槽位 m + top_k + floor(T/(m·hca))（算力口径），两者互相独立
    • 知道三层为什么能并进一次 softmax：各层只是把不同范围的 key 放进同一行分数， 掩码逐行对齐后一次归一化，等价于在并集 [0, i] 上做注意力
    • 默认 csa_block = 0 时注意力仍走 flash_attention，前向逐位不变（且不新增任何参数）
  • 第 50 课结束时，理解 MLA 解耦 RoPE 与权重吸收：
    • cargo run --release -- mla 跑完三节：增量缓存字节账本、吸收的解码算力账本、解耦约束自检
    • 说得清"把 RoPE 从 K 里摘出来单独走低维通路"为什么是吸收的前提—— 旋转会让 K 不再是 latent 的线性函数，而吸收恒等式 q_nope·(c·W_UK) = (q_nope·W_UKᵀ)·c 要求线性
    • 记得住两处 bias 的不同命运：b_k 是逐 head 常数、softmax 里自动抵消； b_v 因 Σp = 1 会整体平移输出、必须补回
    • 算得清两组账：增量缓存 T·(r + n_head·hd_rope)·4（对照全量 2·T·n_head·head_dim·4）， 与吸收后 T 项系数从 2·n_head·r·hd_nope 降到 2·n_head·r（比值趋近 hd_nope）
    • 知道吸收的边界：仅无梯度推理可用、与 QK-Norm 互斥、解耦要求 n_kv_head ∈ {0, n_head}
    • 默认 mla_rope_dim = 0 时不构造 c_qr/c_kr、不消耗随机数，前向逐位不变
