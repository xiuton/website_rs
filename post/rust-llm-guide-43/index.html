第 43 课：FP8 低精度训练（模拟）

本课已落地为可运行代码：src/fp8.rs（E4M3 / E5M2 编解码 + per-block scale + 模拟 matmul 往返；单测跑 cargo test fp8，数量以实际输出为准）+ fp8 子命令 + 训练开关 train.fp8。

⚠️ 必须说清的边界：本模块是纯数值模拟——把张量编成 FP8 的比特再解码回来， 量"若按 FP8 存，数值会差多少、loss 会变差多少"。它不带来任何速度或显存收益： 本仓库的算子全部跑在 CPU 的 f32 上，编解码反而更慢。真实 FP8 训练的收益来自 GPU 的 FP8 tensor core（一条 mma 吃 8 位操作数、吞吐是 bf16 的两倍），本仓库没有 FP8 kernel， 这份收益一分也拿不到。请勿把本课的数字当成性能数据。

与第 33 课的衔接：第 33 课的量化走"整数码 + 缩放因子"（int8/int4，用于推理）； 本课走"浮点码 + 分块缩放"（FP8，用于训练）。

1. 本课要搞懂的问题

  1. FP8 与 int8 有什么本质区别？为什么训练侧偏爱 FP8？
  2. E4M3 与 E5M2 各自适合存什么？为什么 E4M3 没有 Inf？
  3. 整张矩阵共用一个 scale 会出什么问题？MXFP8 的"每 32 元素一个 scale"是怎么来的？
  4. 权重掉到 8 位，loss 会差多少？

2. FP8 不是"8 位整数"，是"8 位浮点"

精度 每参数字节 结构
FP32 4 1 符号 + 8 指数 + 23 尾数
BF16 2 1 符号 + 8 指数 + 7 尾数
FP16 2 1 符号 + 5 指数 + 10 尾数
FP8 (E4M3) 1 1 符号 + 4 指数 + 3 尾数
FP8 (E5M2) 1 1 符号 + 5 指数 + 2 尾数

FP8 沿用浮点的"符号 + 指数 + 尾数"结构，只是把总位宽砍到 8 位。这带来一个对训练 至关重要的性质：它是指数定长的浮点，相对精度在很大范围内恒定（3 位尾数恒给约 2^-4 的舍入上界），不像 int8 那样"范围一大、精度就一律变粗"。

2.1 两种格式的分工

格式 指数位 尾数位 最大值 最小正规数 最小非规格化 Inf 码
E4M3 4 3 448 2⁻⁶ ≈ 1.562e-2 2⁻⁹ ≈ 1.953e-3 无
E5M2 5 2 57344 2⁻¹⁴ ≈ 6.104e-5 2⁻¹⁶ ≈ 1.526e-5 有（0x7C）

分工原则：

  • 权重 / 激活用 E4M3：数值集中在 1 附近，范围够用，优先要精度（多一位尾数）。
  • 梯度用 E5M2：反向的梯度跨好几个数量级，优先要动态范围（多一位指数）。

E4M3 没有 Inf 码是最容易被忽略的特性：它把"指数全 1 + 尾数全 1"这个位置留给了 NaN，所以溢出只能饱和到最大值 448（OCP 规范如此），而不是报 Inf。E5M2 才保留 Inf。

2.2 标准码值对照

cargo run --release -- fp8 第一节打印的代表性数值（与 OCP / NVIDIA 文档一致）：

数值 E4M3 码 解码值 E5M2 码 解码值
1.0 0x38 1.000000 0x3C 1.000000
1.5 0x3C 1.500000 0x3E 1.500000
0.1 0x1D 0.101562（+1.56%） 0x2E 0.093750（−6.25%）
2⁻⁹ 0x01 0.001953 0x18 0.001953
448 0x7E 448.000000 0x5F 448.000000
57344 0x7E 448.000000（饱和） 0x7B 57344.000000
1e9 0x7E 448.000000（饱和） 0x7C inf

读法：0.1 在 E4M3 里只能落到 0.1016（3 位尾数就这个精度）；1e9 在两种格式里都 超范围——E4M3 饱和到 448，E5M2 报 Inf。同一个数在两种格式下的码完全不同， 所以解码必须知道用的是哪种格式。

实现上舍入用手写的 round-to-nearest-ties-to-even（硬件做浮点舍入用的就是这个规则）：

fn round_ties_even(v: f32) -> f32 {
    let f = v.floor();
    let d = v - f;
    if d > 0.5 { f + 1.0 }
    else if d < 0.5 { f }
    else if (f as i64) % 2 == 0 { f }   // 正好在中间：往偶数靠
    else { f + 1.0 }
}

3. 分块缩放：让 8 位装下真实分布

3.1 整张一个 scale 的问题

FP8 的指数是定长的，没有"非规格化到任意小"的余地。如果整张矩阵共用一个 scale：

$$ \text{scale} = \frac{\max|x|}{\text{fmt.max()}}, \quad q = \text{encode}(x / \text{scale}), \quad x' = \text{decode}(q) \cdot \text{scale} $$

那么只要有几个离群大的元素，scale 就被撑大，其余小量级的元素全被压进非规格化区间、 甚至压成 0。

3.2 per-block scale（micro-scaling）

解法是 per-block scale（也叫 micro-scaling，MXFP8 规定每 32 个元素一个 scale）：

块内：scale = max|x_block| / fmt.max()
      q     = encode(x / scale)     // 每元素 1 字节
      x'    = decode(q) * scale

存储开销：32 元素共享一个 f32 scale = 4 字节 / 32 元素 = 1 bit/元素， 总位宽 9 bit，相比 f32 仍是约 3.6 倍压缩。

3.3 实测：块大小怎么选

cargo run --release -- fp8 第二节构造了一个"第 1 行尺度 1.0、最后一行 1e-6"的 合成权重 [256×256]（真实权重不同通道的尺度差异就这么大）：

块大小 SNR (dB) 平均绝对误差 最大绝对误差 占用（f32 的 %）
整张 31.4 1.344e-3 1.332e-1 25.0%
128 31.8 1.292e-3 1.036e-1 25.8%
32 32.5 1.200e-3 9.497e-2 28.1%
1 154.8 3.082e-10 1.192e-7 125.0%

两个必须一起看的点：

  • 块越小误差越小，但 scale 的存储开销越大（块 1 时每个元素配一个 f32 scale， 5 字节/元素，比 f32 还大——那不是量化，只是把 f32 换了个地方存）。 收益与开销必须一起看，这是量化最容易自欺的地方。
  • 注意"整张"与"块 32"的 SNR 只差 1.1 dB。因为 FP8 是浮点、相对精度与 scale 基本 无关；单 scale 的真正代价是把小量级的元素压进非规格化区间直至压成 0，而这在 平均误差里不显眼。要看出差别，得单独统计小量级那半段的相对误差。

3.4 模拟矩阵乘

操作数先各自往返量化、再相乘（累加仍在 f32）：

格式 相对 Frobenius 误差 最大绝对误差
E4M3 3.38% 2.740
E5M2 6.73% 4.632

E4M3 的误差明显更小（3 位尾数 vs 2 位），代价是动态范围小两个数量级。这正是 "前向 E4M3 / 反向 E5M2"的由来。

4. 权重落 FP8 之后，loss 差多少

cargo run --release -- fp8 第三节：训一个小模型（n_embd = 32、n_layer = 2，60064 参数； 默认 300 步：交叉熵 3.6363 → 0.7696），备份全部参数，然后把同一份权重分别按 E4M3 / E5M2（+ 分块 32）往返量化，在同一评测集上重算 loss：

权重要求 验证 CE 困惑度 相对变化 量化张量/元素
E4M3（+ 分块 32） 2.8546 17.368 +0.07% 15 / 58560
E5M2（+ 分块 32） 2.8689 17.617 +0.57% 15 / 58560
f32（原始） 2.8526 17.333 0.00% 0 / 60064

（步数不同数字会略变；关键是量级——权重掉到 8 位只让 loss 动了不到 1%， 这正是 FP8 训练可行的前提。）

注意口径：

  • 这里只量化了权重。真实 FP8 训练还要把激活也压到 8 位（前向 E4M3），那是一份额外误差。
  • 只量化 rank == 2 的矩阵权重：RMSNorm 增益、bias 是一维的，尺度与矩阵权重差几个 数量级，真实 FP8 训练也把它们留在高精度（bf16/f32）。
  • 小的相对变化（甚至略微变好）是正常波动——评测集小、量化扰动小；单测里因此断言的是 |Δ| / before < 5%，而不是"只能变差"。

5. 本仓库实现要点：训练开关 train.fp8

{
  "train": {
    "fp8": true   // 默认 false
  }
}

打开后，训练循环在每步 opt.step() 之后、下次前向之前，把所有二维权重矩阵按 E4M3 + 每 32 元素一个 scale 往返量化回写。语义等价于"权重以 FP8 精度存放，梯度与 优化器状态仍是 f32"。

格式与块大小固定为模块常量 TRAIN_FORMAT / TRAIN_BLOCK（不做成配置项， 避免过度配置化）。再次强调：只做数值模拟，不带来任何加速。

6. 运行与验证

本课的实测数据在 cargo run --release -- fp8 的三节演示里（标准码值对照 → 分块大小 SNR → 权重落 FP8 后的验证 CE），单测跑 cargo test fp8。

常见坑（实测踩出来的）

1. 舍入误差让 amax 元素溢出成 Inf

第一版实现先出现 E5M2 的模拟 matmul 输出 NaN、E5M2 权重量化后验证 CE 变成 NaN。 根因：scale = amax / max 之后 inv = 1.0 / scale 的舍入误差，会让"恰好等于 amax" 的那个元素算出来比 max 大一丁点，E5M2 于是把它编成 Inf——一个元素溢出就把 整张张量污染成 inf/NaN。

修法是编码前先饱和（真实的 FP8 kernel 也是"先按 amax 定 scale 再饱和"）：

let lim = fmt.max();
chunk[k] = encode((data[base + k] * inv).clamp(-lim, lim), fmt);

并补了回归测试 test_block_scale_saturates_instead_of_overflowing_to_inf （E4M3/32、E5M2/32、E5M2/7 × 64 轮随机数据，断言全部有限）。

2. 逐元素相对误差会被近 0 元素放大

test_simulate_matmul_error_is_in_fp8_range 第一版报"单元素相对误差 27295%"。 原因是输出里有接近 0 的元素，逐元素相对误差被除零放大。改用相对输出峰值的绝对误差 （max_abs < 0.2 × peak）后就是干净的。

3. 整张 SNR 会被大元素主导

test_per_block_beats_single_scale_on_wide_dynamic_range 第一版失败：单 scale 与 分块都是 31.8 dB。两个原因：动态范围不够大；以及整张 SNR 被大元素主导，看不出 小量级被压平。修法是加大动态范围，并只统计小量级那半段的平均相对误差。

教训：量化实验里，"用什么指标"比"跑什么数据"更容易出错。同时用 SNR、 相对 Frobenius 误差、相对峰值绝对误差三种口径互相印证，才不容易被单一指标骗过去。

7. 小结与下一课

本课小结

本课给出的是一份"若按 FP8 存，数值会差多少"的数值基准：权重掉到 8 位只让验证 CE 动了 +0.07%（E4M3 + 分块 32）；但本仓库没有 FP8 kernel，这份收益一分也拿不到。

拓展方向

  • 接真 kernel：本课留下的是"可对照的数值基准"。要在 GPU 上拿到真收益，需要把 matmul 换成吃 FP8 操作数的 tensor core kernel（CUDA / Triton 的 float8_e4m3fn）， 并做 per-block scale 的融合。
  • 延迟缩放（delayed scaling）：用历史 amax 的滑动统计来定 scale，比"本块现算"更省。
  • 梯度用 E5M2：本课只覆盖前向的舍入往返；真实 FP8 训练里反向梯度走 E5M2。
  • FP8 与 AMP 共存：本项目的 train.amp（动态损失缩放）与 train.fp8 相互独立，可同时开。
