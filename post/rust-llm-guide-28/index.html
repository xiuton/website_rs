第 28 课：梯度累积 —— 小显存也能跑大 batch

代码位置：src/train.rs（训练循环中的梯度累积逻辑） 代码位置：src/config.rs（TrainConfig.accum_steps）

配置开关：config/config.json → train.accum_steps（1 = 不累积；本仓库当前配置就是 1，下文的 4 是示例值）

1. 本课要搞懂的问题

  1. 为什么大 batch 训练效果好，但显存放不下？
  2. 梯度累积是怎么用多个小 batch 模拟大 batch 的？
  3. 反向的上游梯度为什么要除以 accum_steps？

2. 大 batch 的好处与困境

2.1 好处

  • 梯度估计更准确（噪声更小）
  • 训练更稳定
  • GPU 利用率更高（大矩阵运算效率更高）

2.2 困境

显存占用 ∝ batch_size：

显存 ≈ 模型参数 + 优化器状态 + 激活值(batch_size * T * D * n_layer)

例如 LLaMA-7B 在 batch_size=32 时需要 ~40GB 显存，单卡放不下。

3. 梯度累积的原理

核心思想：不更新参数，累积多个小 batch 的梯度，等效于大 batch。

标准大 batch（batch_size=32）:
  loss = forward(x[0:32])
  loss.backward()
  optimizer.step()

梯度累积（accum_steps=4, micro_batch=8）:
  for i in 0..4:
      loss = forward(x[i*8:(i+1)*8])
      loss.backward()                        # 梯度自动累加（本项目把反向的上游梯度按 1/N 缩放，N = 本窗口实际微批数）
  clip_grad_norm()
  optimizer.step()                           # 累积完才更新
  zero_grad()

3.1 为什么要除以 accum_steps？

loss.backward() 计算的是 d(loss)/d(param)。

如果累积 4 次，梯度会是 4 倍大。乘上 1/4 保证最终梯度等于"用完整大 batch 算一次"的结果。

等效 loss = (loss_1 + loss_2 + loss_3 + loss_4) / 4

实现细节：本项目不缩放 loss 张量本身（打印/日志里的仍是原始 loss），只把 1/N 作为上游梯度注入反向计算，效果与"先 loss/N 再反向"完全一致。

⚠️ 这里的 N 是本窗口实际的微批个数，不是无脑的 accum_steps。最后一个窗口可能不满 （steps % accum_steps != 0），此时若仍按 accum_steps 缩放，尾窗的梯度就被多除了 accum_steps / 实际值——等效于那一步的学习率被悄悄调小，而且不会有任何报错。 所以训练循环里传的是 train::accum_window(step, accum, steps)：

pub(crate) fn accum_window(step: usize, accum: usize, steps: usize) -> usize {
    let accum = accum.max(1);
    let start = (step / accum) * accum;                  // 窗口按绝对步号切分
    accum.min(steps.saturating_sub(start)).max(1)        // 尾窗取剩余步数（至少 1）
}

窗口按绝对步号切分（[0,accum) [accum,2·accum) …），所以断点续训从窗口中间开始时 算出来的窗口大小仍与串行一致（这个语义由 train::tests::test_accum_window_shrinks_only_the_tail 守住）。

4. 实现要点

4.1 训练循环修改

for step in 0..steps {
    let (x, y) = sample_batch(rng);
    // accum > 1 时：返回的仍是未缩放的 loss（打印用原始值），
    // 反向时把 1/N 作为上游梯度注入，等效于 loss/N 的梯度；
    // N = accum_window(step, accum, steps) 是本窗口**实际**的微批个数（尾窗会小于 accum）
    let loss = forward_loss(&model, &x, &y, batch_size, block_size,
                            accum_window(step, accum, cfg.steps));
    loss.backward();  // 梯度累加到现有梯度上

    // 只在累积窗口结束时裁剪 + 更新 + 清零；
    // 最后一步即使不满 accum 也强制收尾，否则尾巴那批梯度会被丢掉、从未参与更新
    if (step + 1) % accum == 0 || step + 1 == cfg.steps {
        clip_grad_norm(&params, cfg.grad_clip);
        opt.step();
        opt.zero_grad();
        scheduler.step();   // 调度器与优化器同步：只在真正更新后前进
    }
}

更新条件 (step + 1) % accum == 0 || step + 1 == steps 与 accum_window 是自洽的： 每个窗口末尾各触发一次更新，且各窗口的微批数之和恰好等于总步数（单测里对多组 (steps, accum) 逐一核对了这条不变式）。

4.2 有效 batch size

有效 batch_size = micro_batch_size * accum_steps

例如 batch_size=8, accum_steps=4 → 有效 batch_size = 32。

4.3 学习率调度

学习率调度器按"更新次数"计数（不是每个 micro-batch）：scheduler.step() 和 optimizer.step() 一样， 只在累积窗口结束的那个分支里调用（src/train.rs 的 train_transformer），也就是每 accum_steps 步才前进一次。 这样 cfg.steps 表示的仍是"总更新步数"，warmup 与 cosine 衰减的进度也都按更新步计算。

5. 梯度累积 vs 数据并行

梯度累积 数据并行（DDP）
硬件 单卡 多卡
通信 无 AllReduce 梯度
速度 线性慢（N 步才更新一次） 接近线性加速
映射 模拟大 batch 真正的大 batch

梯度累积是"穷人版"的大 batch 训练：不需要多卡，但训练速度会变慢（每 accum_steps 步才更新一次）。

6. 配置示例

{
  "train": {
    "batch_size": 8,
    "accum_steps": 4
  }
}

有效 batch_size = 32，但每步只占用 batch_size=8 的显存。

7. 小结与下一课

本课小结

  • 梯度累积用多个小 batch 模拟大 batch，解决显存不足问题
  • 反向的上游梯度乘 1/N 保证梯度等效（N = 本窗口实际微批数，尾窗不足 accum_steps 时按实际值；loss 张量本身不缩放，日志里仍是原始 loss）
  • 每 accum_steps 步才做一次 optimizer.step() + zero_grad()
  • 有效 batch_size = micro_batch_size * accum_steps
  • 代价：训练速度变慢（更新频率降低）

拓展方向

核心内容已全部实现，这里是进阶拓展。

  1. 扫 accum_steps：把 train.accum_steps 在 1 / 2 / 4 / 8 各跑一遍（batch_size 固定为 8），对比有效 batch 与实际耗时——验证第 5 节那张表里"线性慢"的结论。
  2. 看尾窗：把 steps 设成不是 accum_steps 整数倍的值（如 steps = 10, accum_steps = 4），打印 accum_window(step, accum, steps) 的返回序列，确认只有尾窗变小、其余窗口不变。
  3. 核对不变式：给 accum_window 补一条单测，对多组 (steps, accum) 断言"各窗口微批数之和 == steps"（4.1 节提到已有类似断言）。
  4. 和 scheduler 对齐：在 scheduler.step() 处打印计数，确认它每 accum_steps 步才前进一次（4.3 节的语义）。
