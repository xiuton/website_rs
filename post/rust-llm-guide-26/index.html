第 26 课：混合精度训练（AMP）—— 用半精度加速，用全精度保底

代码位置：src/train.rs（MixedPrecision 结构体）

算法论文：Mixed Precision Training (Micikevicius et al., 2018)

1. 本课要搞懂的问题

  1. 为什么 FP16 训练比 FP32 快？快多少？
  2. 为什么不能全程用 FP16？会出什么问题？
  3. 什么是损失缩放（Loss Scaling）？为什么需要它？
  4. 动态损失缩放是怎么自动调整 scale 的？

2. 数值精度对比

格式 位数 数值范围 精度
FP32 32 位 ±3.4e38 ~7 位十进制
FP16 16 位 ±65504 ~3 位十进制
BF16 16 位 ±3.4e38 ~2 位十进制

2.1 FP16 的优势

  • 显存减半：同样大小的模型/激活值，显存占用减半
  • 计算加速：GPU 的 Tensor Core 对 FP16 有 2-8× 的吞吐提升
  • 带宽减半：内存/显存带宽需求减半

2.2 FP16 的问题

  • 数值范围小：最大值只有 65504，梯度容易溢出（NaN/Inf）
  • 精度低：小梯度（~1e-7）会被舍入为 0（FP16 最小正规数 ~6e-8）

3. 混合精度训练的三板斧

3.1 前向/反向用 FP16

把模型权重和激活值转成 FP16，矩阵乘法在 FP16 下执行。

3.2 主权重用 FP32

优化器更新时需要高精度：

w_new = w - lr * grad    # lr=1e-4, grad=1e-6 → 更新量=1e-10

在 FP16 下，1e-10 会被舍入为 0，参数根本不会更新！

所以主权重保持 FP32，更新后再转回 FP16。

3.3 损失缩放（Loss Scaling）

问题：训练后期梯度值很小（1e-51e-7），在 FP16 下会下溢为 0。

解决：loss 乘一个大数（scale），让梯度数值范围移到 FP16 可表示区间：

loss_scaled = loss * scale           # 例如 scale = 65536
loss_scaled.backward()               # 梯度也被放大了 scale 倍
grad = grad / scale                  # 更新前除回来
optimizer.step(grad)

4. 动态损失缩放

固定 scale 不够灵活：太大会溢出，太小会下溢。

动态策略：

初始 scale = 2^16 = 65536

每 N 步检查梯度：
  - 无 NaN/Inf → growth_steps++
    - growth_steps >= 阈值 → scale *= 2（尝试更大）
  - 有 NaN/Inf → scale /= 2（缩小），跳过本步更新

直觉：scale 像一个"弹簧"，自动在"太大溢出"和"太小下溢"之间找平衡。

5. 本项目的实现

AMP 这条线由 MixedPrecision 结构体实现动态损失缩放；存储半精度（bf16）是另一条独立的线 （TrainConfig 的 bf16 开关，见 5.1 小节），两者互相独立、可同时开：

pub struct MixedPrecision {
    pub scale: f32,           // 当前缩放因子
    init_scale: f32,          // 初始缩放因子（2^init_scale_log2）
    growth_interval: usize,   // 连续无溢出步数阈值
    growth_steps: usize,      // 当前计数
    min_scale: f32,           // 最小 scale（1.0）
    max_scale: f32,           // 最大 scale（2^24）
}

使用方式：

let mut amp = MixedPrecision::new(16, 2000); // 初始 2^16, 每 2000 步翻倍

let scaled_loss = amp.scale_loss(&loss);
scaled_loss.backward();

if amp.check_and_update(&params) {
    optimizer.step();  // 无溢出，正常更新
} else {
    optimizer.zero_grad(); // 有溢出，跳过本步
}

集成状态：MixedPrecision 已接入 train_transformer() 训练循环（train.amp 开关，默认开启）， 完整链路是：scale_loss() 放大 loss → 反向 → check_and_update() 检查溢出（含 Inf/NaN 就丢弃本步、 不更新参数，并把 scale 减半）→ unscale_gradients() 把梯度除回真实尺度 → clip_grad_norm() 裁剪 → AdamW::step() 更新。scale 在连续 growth_interval 步无溢出后翻倍，上限 2²⁴。

本项目算子内全程 f32 计算（无论数据存 f32 还是 bf16，见 5.1），所以这里的作用点在 溢出保护与裁剪正确性，而不是算力： scale 恒为 2 的幂，f32 下乘以/除以 2^k 是精确的指数移位，整条反向链路逐位等于未缩放时的结果 （train::tests::test_amp_loss_scaling_is_numerically_transparent 就在断言这一点）。 反缩放那一步是正确性刚需：梯度裁剪的阈值是按真实梯度量级定的，带着 scale 去裁剪等于把阈值放大 2¹⁶ 倍。

这里有个容易被忽略的前提：每个计算节点都必须消费自己攒到的上游梯度。GPU 常驻显存的输出头把 hidden @ Wᵀ 与 softmax + 交叉熵融合成一个节点（Tensor::external_scalar_loss）， 它的反向是「按上游梯度 = 1 算好、再整体乘回去」；这一步若漏了，scale_loss() 乘上去的 2¹⁶ 会被静默 丢掉，而紧接着的 unscale_gradients() 又照除不误——梯度整体偏小 2¹⁶ 倍。AdamW 对梯度的统一缩放 不敏感（一阶/二阶矩同比缩放），表面上"还在训练"，但梯度裁剪的阈值实际失效了，训练轨迹因此偏离 （实测同一份数据：无 AMP 2.8965 / 有 AMP 2.9655）。融合节点与 Tensor::mul_scalar 的这个组合由 tensor::tests::test_external_scalar_loss_consumes_upstream_gradient 直接钉住。

损失缩放、溢出跳步、梯度反缩放这三件事并不依赖半精度类型，已经完整可用； bf16 的存储与显存收益也已作为独立开关落地（TrainConfig.bf16），见下节。

5.1 真 u16 bf16 存储（批次 10b）

TrainConfig 的 bf16 开关（默认 false）开启后，train_transformer() 在建模 / 断点恢复完成后把 全部参数张量原地转为真 u16 bf16 位模式存储——参数内存真实减半。核心约定是 decode-at-boundary（bf16 只存在于存储层）：

  • 存储层：Tensor 的数据槽是 Shared<Buffer>，enum Buffer { F32(Vec<f32>), Bf16(Vec<u16>) }。 变体住在共享锁槽内，to_bf16() 原地换变体——模型各层与优化器参数表拿的是同一批 Arc 句柄，一处转换、全体生效（必须放在 resume 之后，否则 checkpoint 恢复按 f32 写入会盖掉转换）。
  • 入口 decode：算子统一用 decode() 拿只读 f32 视图（DataGuard），bf16 槽位在锁内并行 解码、立即放锁；写入点用 decode_mut()（DataGuardMut），Drop 时并行 encode 回 u16—— SGD/AdamW 就是这样在 f32 下算完更新再截断回写的（master weights 语义）。
  • 出口 encode：算子出口统一走 new_like(&self, ...)，按源张量 dtype() 决定是否 encode 落盘， 输出继承左操作数 / 主输入的 dtype。bf16 进、bf16 出；f32 张量路径零转换、语义不变。
  • 计算与梯度恒 f32：算子内部全程 f32；grad 缓冲与优化器动量恒 f32，不参与该约定； GPU 路径同样恒 f32。编解码用 RNE（round-to-nearest-even），见 f32_to_bf16 / bf16_to_f32。

与 AMP 的关系：bf16 管存储（省显存），amp 管溢出保护（loss scaling）。bf16 数值范围 与 f32 相同、理论上不需要 loss scaling，但 AMP 链路保留无成本，两者可同时开。

定向测试 tensor::tests::test_bf16_*（cargo test bf16；数量为写作时快照，以实际输出为准）覆盖：RNE 编解码往返与取偶、真 u16 存储与克隆句柄 同步、出口 dtype 继承、decode_mut 回写、梯度恒 f32。

6. BF16 vs FP16

FP16 BF16
数值范围 ±65504 ±3.4e38（和 FP32 一样）
精度 ~3 位十进制 ~2 位十进制
需要 Loss Scaling ✅ 是 ❌ 不需要
硬件支持 几乎所有 GPU A100+, H100+, TPU

BF16 因为数值范围和 FP32 一样，不需要 Loss Scaling，是现代大模型训练的首选。

7. 小结与下一课

本课小结

  • 混合精度：前向/反向用低精度，主权重用 FP32
  • Loss Scaling 防止小梯度在 FP16 下下溢为 0
  • 动态 scale：无溢出时翻倍，有溢出时减半
  • BF16 不需要 Loss Scaling（数值范围和 FP32 一样）
  • 存储半精度：TrainConfig.bf16 把参数转真 u16 bf16（内存减半），算子边界 decode/encode，计算与梯度恒 f32
  • 现代大模型训练几乎都用混合精度（BF16 + FP32 主权重）

拓展方向

核心内容已全部实现，这里是进阶拓展。

  1. growth_interval 扫参：把 MixedPrecision::new(16, 2000) 的第二个参数改成 50 / 500 / 2000，观察 scale 的爬升速度与溢出跳步次数（train.amp 开着跑）。
  2. 关掉 AMP 对比：保持同一 seed，分别在 train.amp = true / false 下跑一遍，核对第 5 节里那条实测 loss（2.8965 / 2.9655）。
  3. 单独测 bf16 存储：只开 TrainConfig.bf16（train.amp 关掉）跑一次，对比参数内存占用是否真的减半（5.1 节的 decode-at-boundary 约定）。
  4. 看 scale 的幂次：在 check_and_update 里临时打印 scale.log2()，确认它全程是 2 的整数次幂（第 5 节说 f32 下乘除 2^k 是精确的指数移位）。
