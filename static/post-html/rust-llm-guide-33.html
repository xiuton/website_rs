第 33 课：量化技术（Quantization）

本课已落地为可运行代码：src/quant.rs（单测跑 cargo test quant，数量以实际输出为准）+ quant 子命令——RTN / Hessian 量化 / AWQ 三种 weight-only 量化、int8 / int4、校准集（Hessian XᵀX、act-order、阻尼、分块）、逐层误差报告与落盘。 与已有代码的衔接：量化作用于 src/tensor.rs 中的权重数据（Vec<f32>）， checkpoint（src/checkpoint.rs，LLMCP2）头部会记一笔 QuantMeta（位宽 + 算法，旧档为 None）： 存档里写出的仍是 f32 权重，需要省显存时按这份记录调 requantize_after_load 重放一次量化即可。

1. 为什么需要量化？

一个 7B 参数的模型，以 FP32 存储需要 28GB 显存（7B × 4字节），以 FP16 也需要 14GB。 这意味着普通消费级显卡（如 RTX 3060 12GB）根本放不下一个 7B 模型。

量化的核心思想：用更少的比特数表示每个参数。

精度 每参数字节 7B 模型大小 精度损失
FP32 4 28 GB 无
FP16/BF16 2 14 GB 极小
INT8 1 7 GB 小
INT4 0.5 3.5 GB 中等
INT2 0.25 1.75 GB 较大

2. 量化的基本原理

2.1 线性量化公式

$$ x_q = \text{round}\left(\frac{x}{s}\right) + z $$

其中：

  • $s$ 是缩放因子（scale）
  • $z$ 是零点（zero point）
  • $x_q$ 是量化后的整数值

反量化（从整数恢复浮点近似值）：

$$ \hat{x} = s \cdot (x_q - z) $$

2.2 对称量化 vs 非对称量化

对称量化（Symmetric）：零点固定为 0，数据范围关于 0 对称 $$ s = \frac{\max(|x|)}{2^{b-1} - 1}, \quad z = 0 $$

非对称量化（Asymmetric）：零点可变，适合数据分布不对称的情况 $$ s = \frac{\max(x) - \min(x)}{2^b - 1}, \quad z = \text{round}\left(\frac{-\min(x)}{s}\right) $$

3. 量化粒度

粒度 说明 适用场景
Per-Tensor 整个张量共享一组 scale/zero_point 简单但精度低
Per-Channel 每个输出通道一组 scale/zero_point 权重量化常用
Per-Group 每 g 个元素一组（如 g=128） Hessian 量化/AWQ 常用
Per-Token 每个 token 的激活值一组 激活值量化

直觉：张量不同位置的数值范围差异很大。Per-Group 量化给每 128 个元素一个独立的 scale，比整个张量共用一个 scale 精度高得多。

4. 量化方法分类

4.1 训练后量化（Post-Training Quantization, PTQ）

模型训练完后直接量化，不需要重新训练。

Round-to-Nearest（RTN）

最简单的量化方法：直接四舍五入到最近的整数格点。

$$ W_q = \text{round}(W / s) \cdot s $$

缺点：INT4 下精度损失大（误差是逐列独立的，没有误差补偿）。

Hessian 量化（2022）

基于**二阶信息（Hessian）**的逐层量化：量化某一列时，用 Hessian 信息补偿剩余列的误差。

核心思想（OBQ/OBS 方法）：

  1. 量化权重 $w_q$ 的某一列
  2. 未量化的列用 Hessian 逆矩阵调整，补偿量化误差
  3. 逐列推进，每列量化后都更新剩余列

$$ \delta_{\text{col}} = -\frac{w_q - \text{quant}(w_q)}{[H^{-1}]{qq}} \cdot (H^{-1}){:,q} $$

优势：INT4 下精度远好于 RTN，是目前最广泛使用的 PTQ 方法之一。

AWQ（Activation-aware Weight Quantization，2023）

核心洞察：不是所有权重同等重要。对应激活值大的权重通道更重要（对输出影响更大）。

做法：量化前先对权重按激活值的重要性做缩放（per-channel scaling），再量化。

$$ W' = W \cdot \text{diag}(s), \quad s_j = \left(\frac{|X_j|{\text{mean}}}{\max(|X|{\text{mean}})}\right)^{\alpha} $$

GGUF / llama.cpp

实际部署中最流行的量化格式（由 llama.cpp 项目定义）：

类型 说明
Q4_0 4-bit 对称量化，每 32 个权重一组
Q4_K_M 4-bit，K-quant，中等质量
Q5_K_M 5-bit，K-quant，较高质量
Q8_0 8-bit 对称量化

4.2 量化感知训练（Quantization-Aware Training, QAT）

在训练过程中模拟量化效果，让模型"学会"适应低精度表示。

前向传播：
  W_fake = quantize(W_real)   // 前向用量化权重（模拟推理）
  y = x @ W_fake

反向传播：
  grad 通过 STE (Straight-Through Estimator) 传回 W_real
  W_real -= lr * grad         // 更新原始高精度权重

STE（直通估计器）：量化操作的梯度在数学上是 0（round 不可微），STE 假设梯度直接穿过量化层，即 $\frac{\partial W_q}{\partial W} \approx 1$。

4.3 量化在 LLM 推理中的实际应用

原始 FP16 模型 (14GB)
  ↓ Hessian 量化 / AWQ / GGUF 量化
INT4 模型 (3.5GB)
  ↓ 在 RTX 3060 (12GB) 上加载
  ↓ 推理时反量化到 FP16 做矩阵乘
  ↓ 性能损失 < 2%（perplexity 增加 < 0.5）

5. INT8 量化详细过程

以权重矩阵 $W \in \mathbb{R}^{m \times n}$ 的 Per-Channel INT8 量化为例：

对于每个输出通道 j (共 n 个):
  1. 计算该通道的最大绝对值: max_j = max(|W[:, j]|)
  2. 计算缩放因子: scale_j = max_j / 127
  3. 量化: W_q[:, j] = round(W[:, j] / scale_j)   // 范围 [-127, 127]
  4. 存储: W_q (INT8) + scale (FP32, 每通道一个)

推理时:
  1. 反量化: W_hat[:, j] = W_q[:, j] * scale_j    // 恢复到 FP16
  2. 正常矩阵乘: Y = X @ W_hat

6. 混合精度量化（Mixed-Precision Quantization）

不同层对量化的敏感度不同：

  • Embedding 层和输出层对精度敏感（直接影响词预测），通常保持 FP16
  • 注意力层中等敏感，可用 INT8
  • FFN 层参数量最大但相对鲁棒，可用 INT4
Embedding (FP16) → Attention (INT8) → FFN (INT4) → ... → Output (FP16)

7.1 代码结构

组件 位置 说明
QBits / QAxis / QuantMeta quant.rs 位宽、量化轴、元信息（位宽 + 算法名）
quantize_channel_sym / quantize_row_sym quant.rs 对称量化 + 反量化（逐通道 / 逐 token）
pack_u8 / unpack_u8 / pack_u4 / unpack_u4 quant.rs 位打包与往返
hess_quantize_with_hinv quant.rs Hessian 量化：Cholesky 逆 + 逐通道误差补偿 + 分块 + act-order
awq_best_alpha quant.rs AWQ：按代理误差在 0~1 网格搜索最优缩放指数 α
Calibration quant.rs Hessian XᵀX + 激活均值 + 合并，供 Hessian 量化/AWQ 校准
Transformer::quantize_weights / dequantize_weights model.rs 逐层量化 / 反量化（挂到模型权重上）
requantize_after_load checkpoint.rs 加载后按 QuantMeta 重放量化（存档写 f32，省显存时重放）

退化诚实性：只有拿到全矩阵 Hessian 才是真 Hessian 量化——对角 Hessian 的 $H^{-1}$ 是对角阵， 补偿量恒为 0，hess_quantize 内部直接走 hinv = None，码值与 RTN 逐位相同；缺校准统计同样退回 RTN。 因此 Linear::quantize_weight 只在 HessianKind::Full 时才把该层记成 QuantMethod::Hess， 否则如实记 Rtn；QuantSummary::degraded 统计"请求的算法没真正生效"的层数， describe() 会在摘要里追加警告（见 src/layers.rs 的 real_hess 判定）。 校准规模默认 CalibOpts::max_tokens = 4096（该量化论文常用量级）：512 时 Hessian 的 通道协方差估计噪声明显，补偿质量打折。

7.2 CLI 用法

# RTN 直接取整（不需要校准集）
cargo run --release -- quant --bits int8 --method rtn

# Hessian 量化（默认 64 样本校准 + act-order + 阻尼）
cargo run --release -- quant --bits int4 --method hess --eval

# AWQ（逐层搜索最优 α）
cargo run --release -- quant --bits int8 --method awq --eval

# 落盘量化权重（out_dir/quant.ckpt）
cargo run --release -- quant --bits int8 --method hess --out out_dir/quant.ckpt

8. 小结与下一课

本课小结

  • 量化的本质是"用更少的比特表示每个参数"：FP32 的 7B 模型 28GB，INT8 掉到 7GB、INT4 掉到 3.5GB
  • 两条基本口径：对称量化（z = 0，权重常用）与非对称量化（z 可变，适合分布不对称的激活）
  • 粒度决定精度：Per-Tensor → Per-Channel → Per-Group（Hessian / AWQ 常用）→ Per-Token
  • PTQ 三条路线：RTN（最简单）、Hessian（逐列误差补偿，INT4 下远好于 RTN）、AWQ（按激活重要性缩放）
  • QAT 用 STE 让梯度穿过 round，让模型"学会"适应低精度
  • 本仓库把上面原理全部落地为 src/quant.rs + quant 子命令，并有退化诚实性约束：只有拿到全矩阵 Hessian 才记成 Hess，否则如实记 Rtn 并由 degraded 统计（§7.1）

拓展方向

核心内容已全部实现（src/quant.rs + quant 子命令），这里是进阶拓展。

  1. 实现 INT8 量化：写一个函数，接受 FP32 张量，输出 INT8 量化值 + scale，再实现反量化。
  2. 量化误差分析：对比原始 FP32 权重和 INT8 反量化后的权重，计算 MSE 和最大误差。
  3. Per-Channel vs Per-Tensor：分别用两种粒度量化同一个权重矩阵，对比精度差异。
  4. PTQ 推理对比：将模型权重 INT8 量化后做推理，对比量化前后的 loss / 困惑度。
  5. 换一套数值表示：本课的量化是"整数码 + scale"这条线（int8 / int4）；训练侧还有另一条线—— 8 位浮点（FP8，E4M3 / E5M2），见第 43 课。对比两者在误差分布上的差别： 定点量化的误差是绝对均匀的，浮点的相对误差才均匀，所以 FP8 能装下跨越几个数量级的梯度。
