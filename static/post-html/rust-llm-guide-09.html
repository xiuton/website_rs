第 9 课：注意力机制 —— 让 token 互相"看"

代码位置：src/attention.rs（MultiHeadAttention::forward 中的投影与注意力算子调用） 底层算子：src/tensor.rs（flash_attention / permute / matmul） 掩码构造：src/model.rs（Transformer::forward_core）

1. 本课要搞懂的问题

  1. 为什么一个 token 需要"看"别的 token？注意力到底在算什么？
  2. Query / Key / Value 是什么？为什么不能直接用 x 打分？
  3. 为什么要除以 √d_k？softmax 在干什么？
  4. 为什么 Transformer 只能看过去？-inf 掩码怎么实现？

2. 从词向量到"上下文向量"

第 12 课会把每个 token 嵌入成一个向量，但 Embedding 查表得到的向量只代表这个 token 自己：它不知道周围发生了什么。"bank" 到底是"河岸"还是"银行"，单看它自己无法判断，必须结合上下文。

注意力要做的事：让每个位置根据内容，从其他位置"收集"信息。输出不再是"我自己的向量"，而是"我 + 我关注的别人的向量的加权混合"。

3. 检索的视角：Query / Key / Value

注意力最直观的类比是图书馆检索：

角色 类比 数学含义
Query（查询）Q 你输入的"关键词" 我想要什么样的信息
Key（键）K 每本书的"标签" 我能提供什么样的信息
Value（值）V 书的内容 真正被取走的信息

流程：拿 query 去和所有 key 比对相似度 → 得到权重 → 按权重把 value 加权求和。

我们的模型里 Q、K、V 都来自同一个输入 x（每个位置既当"提问者"又当"被看者"），这叫自注意力（Self-Attention）。

4. Q / K / V 投影：三个角色各学各的表示

直接用 x 当 Q、K、V 行不行？可以，但不好——三个角色应该学不同的表示。所以每个角色先过一层可学习的线性投影（Linear: y = xW + b）：

// 1. 投影得到 Q、K、V
let q = self.c_q.forward(x).reshape(vec![b, t, d]); // [B, T, D]
let k = self.c_k.forward(x).reshape(vec![b, t, d]);
let v = self.c_v.forward(x).reshape(vec![b, t, d]);
  • c_q / c_k / c_v 是三个独立的 Linear::new(D, D)（MultiHeadAttention 结构体里的字段），各有自己的权重和偏置，在训练中学习
  • Linear::forward 对 3D 输入会自动展平成 [B*T, D] 计算再还原 3D；这里的 reshape(vec![b, t, d]) 保证形状明确是 [B, T, D]
  • D = n_embd。模型配置 TransformerConfig::tiny：n_embd = 64，n_head = 4 → head_dim = 16（第 10 课讲怎么拆头；本课先假设只有一个头，公式层面 H = 1）

5. 打分：scores = Q·Kᵀ / √d_k

query 和 key 的相似度用点积衡量：q_i · k_j 越大越相似。一次性算所有两两相似度，就是矩阵乘法：

S = Q · Kᵀ / √d_k
  • Q: [T, d_k]，K: [T, d_k] → Kᵀ: [d_k, T] → S: [T, T]
  • S[i][j] = (q_i · k_j) / √d_k：第 i 个查询对第 j 个键的"原始分数"

对应代码：

// 实际实现：打分 → 加掩码 → softmax → 加权求和 被融合成一个算子
//   （调用点 src/attention.rs，算子定义 src/tensor.rs 的 Tensor::flash_attention）
let out = Tensor::flash_attention(&q, &k, &v, mask, 32);
  • 算子内部依次做：Q' = Q/√d_k → S = Q'·Kᵀ（3D 批量矩阵乘）→ P = softmax(S + M) → O = P·V，与上面的公式逐项等价
  • 原先分散写的 permute（得到 Kᵀ）/ matmul（Q·Kᵀ）/ mul_scalar（缩放）这一步已经被上面这个融合算子取代；这些基础算子本身仍在 src/tensor.rs 中，只是不再出现在注意力路径上

5.1 手算例子（d_k = 2，两个 token）

Q = [ [1, 0],          K = [ [1, 0],          V = [ [1, 0],
      [0, 1] ]               [0, 1] ]               [0, 1] ]

Q·Kᵀ = [ [1, 0],
         [0, 1] ]

除以 √2 后：S = [ [0.707, 0    ],
                 [0,     0.707] ]

softmax 按行归一化（见第 7 节）后，第 1 行 ≈ [0.670, 0.330]，第 2 行 ≈ [0.330, 0.670]——即"每个位置主要关注自己"（对角线），很符合直觉。

6. 为什么要除以 √d_k

假设 q、k 每个维度独立、均值 0、方差 1。两个 d_k 维向量的点积：

Var(q·k) = Var(Σ q_i·k_i) = d_k          →  标准差 = √d_k
d_k 点积的标准差 后果
小（如 2） 1.4 softmax 分布温和，梯度健康
大（如 64） 8 点积数值大、分布"尖"，softmax 趋向 one-hot（一个 1 其余 0），梯度趋近 0，学不动
  • 除以 √d_k 把方差拉回 1，softmax 保持"温和"的分布
  • 所以这个公式叫 Scaled Dot-Product Attention——缩放点积注意力

7. softmax 归一化：把分数变成权重

原始分数可正可负、量纲不定，不能直接当权重。softmax 把每一行变成非负且和为 1 的概率分布：

a_ij = exp(S_ij) / Σ_j' exp(S_ij')

含义：第 i 个查询给第 j 个键的"注意力权重"，一行加起来等于 1。

7.1 数值稳定技巧

exp 对大的正数会爆炸（如 exp(1000) = 无穷大），所以先减去每行最大值——数学上不改变结果（分子分母同除 exp(max)）：

// softmax_last_dim：沿最后一维逐行独立归一化
for r in 0..rows {
    let mut maxv = f32::NEG_INFINITY;
    for j in 0..d {
        maxv = maxv.max(sd[r * d + j]);                    // 1. 找行最大值
    }
    let mut sum = 0.0;
    for j in 0..d {
        out_data[r * d + j] = (sd[r * d + j] - maxv).exp(); // 2. 减 max 再 exp
        sum += out_data[r * d + j];
    }
    for j in 0..d {
        out_data[r * d + j] /= sum;                        // 3. 归一化
    }
}

稳定版公式：

softmax(x)_i = exp(x_i - max x) / Σ_j exp(x_j - max x)

反向传播公式（softmax_last_dim 的 backward 里已实现）：∂x_i = s_i·(g_i − Σ_j g_j·s_j)，其中 s 是 softmax 输出、g 是上游梯度。这正是第 2 课自动微分的用武之地。

8. 加权求和：out = A·V

把权重矩阵 A 作用到 V 上：

out_i = Σ_j a_ij · v_j

即"每个输出 = 所有位置 V 的凸组合"（权重非负、和为 1）。这一步与前面的打分、掩码一起都在同一个融合算子里完成：

// softmax + 加权求和：融合在 flash_attention 内部（src/tensor.rs 的 Tensor::flash_attention）
let out = Tensor::flash_attention(&q, &k, &v, mask, 32); // [B*H, T, head_dim]

至此，注意力 = 内容相关的可学习加权平均：每个位置根据 query 与各 key 的相似度，从所有 value 里"取"信息。

9. 因果掩码：为什么 Transformer 只能看过去

Transformer 是自回归语言模型：预测第 t 个 token 时，条件只能是它之前的 token：

P(token_t | token_1, ..., token_{t-1})
  • 训练时我们把整段文本并行喂入（这样才快！）。如果不加限制，位置 t 会"偷看"位置 t+1 的答案——信息泄漏，模型退化成"抄答案"
  • 解决办法：让位置 i 的查询看不到 j > i 的键——这就是因果掩码（causal mask）

9.1 掩码长什么样

Transformer::forward_core 里构造（t_total = t + base，训练时 base = 0）：

let mut mask_data = vec![0.0f32; t * t_total];
for i in 0..t {
    for j in 0..t_total {
        if j > i + base {
            mask_data[i * t_total + j] = f32::NEG_INFINITY;
        }
    }
}
let mask = Tensor::from_vec(mask_data, vec![t, t_total]);

以 t = 4 为例，mask 是这样一个矩阵：

查询 i \ 键 j j=0 j=1 j=2 j=3
i=0 0 -inf -inf -inf
i=1 0 0 -inf -inf
i=2 0 0 0 -inf
i=3 0 0 0 0

对角线及以下（j ≤ i）是 0，未来位置（j > i）是 -inf。

9.2 为什么是 -inf 而不是把列删掉

softmax 里 exp(-inf) = 0，被掩码位置的注意力权重精确为 0——"看不见"等价于"权重为 0"。同时张量形状保持不变，可以继续走统一的批量矩阵运算。

// mask 是 Option<&Tensor>：**两条路径都真的消费它**——
// CPU 分块核在核内把掩码行加到打分上（有掩码时可见性完全由掩码决定，不再另按因果截断）；
// GPU 常驻 / probe 录制路径按真实掩码 buffer 消费（没传掩码时由算子自己物化一张因果掩码）。
let out = Tensor::flash_attention(&q, &k, &v, mask, 32); // src/attention.rs

掩码被消费时同样用到第 3 课的广播：mask 形状 [T, T_total] 自动广播到 [B*H, T, T_total] 的每一个"批"（每个头共享同一张掩码）；-inf 位置 exp(-inf) = 0，注意力权重精确为 0。 传 None 时 CPU 分块核才退回核内后缀因果快路（query i 只看 j <= i + visible_before）——这也是视觉塔必须显式传一张全 0 掩码才能拿到真正双向注意力的原因（见 第 41 课）。 （代码里的 base 是 KV cache 引入的偏移，第 25 课讲解；训练时 base = 0。）

10. 公式 ↔ 代码 总对照

Attention(Q, K, V) = softmax( (Q·Kᵀ / √d_k) + M ) · V
数学 Rust 代码（MultiHeadAttention::forward）
Q = x·W_Q self.c_q.forward(x).reshape(vec![b, t, d])
K = x·W_K，V = x·W_V c_k / c_v 同理
Kᵀ 融合算子内部完成
Q·Kᵀ / √d_k 融合算子内部完成（先把 Q 乘 1/√d_k，再做批量矩阵乘）
+ M（因果掩码） mask 作为参数传入融合算子
softmax 融合算子内部完成
·V 融合算子内部完成
后 5 行整体 Tensor::flash_attention(&q, &k, &v, mask, 32)（调用点 src/attention.rs，算子定义 src/tensor.rs）

12. 小结与下一课

融合算子：flash_attention

训练中每步的注意力计算调用的是 Tensor::flash_attention（定义在 src/tensor.rs，调用点 src/attention.rs）， 它把"打分 → 加掩码 → softmax → 加权求和 V"四步融合成一个算子：内部先算 Q' = Q/√d_k， 再做 S = Q'·Kᵀ → P = softmax(S + M) → O = P·V，全程走矩阵乘内核，反向同样全用矩阵乘。 （另有融合算子 Tensor::masked_softmax（src/tensor.rs），它把"加掩码 + softmax"合成一个算子， 用在 MLA 吸收路径与 CSA 稀疏注意力上；整行都被 -inf 淹没时它输出全 0 而不是 NaN。）

本课小结

  • 注意力 = 内容相关的加权平均：Q 问、K 答、V 给内容
  • scores = Q·Kᵀ/√d_k：点积打分，缩放防止 d_k 大时 softmax 饱和
  • softmax：分数 → 权重（非负、和为 1）；先减 max 保证数值稳定
  • 因果掩码：未来位置填 -inf → softmax 后权重为 0 → 模型只能看过去

拓展方向

核心内容已全部实现，这里是进阶拓展。

  1. 手算：取第 5.1 节的 2×2 例子，写出 softmax 后每一行的权重，再算出最终的加权求和结果，对照公式逐项核对。
  2. 修改 forward_core 里的掩码条件 j > i + base 为 j >= i + base（禁止"看自己"），思考对训练会有什么影响（提示：每个位置的预测将只能依赖更早的 token）。
  3. 临时改 softmax_last_dim：去掉"减最大值"那一步，用大数（如 1000）做输入，观察溢出/精度问题，验证数值稳定技巧的必要性。
  4. 阅读 softmax_last_dim 的反向代码，对照公式 ∂x_i = s_i·(g_i − Σ_j g_j·s_j) 逐行核对。
