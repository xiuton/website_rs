第 42 课：知识蒸馏（Knowledge Distillation）

本课已落地为可运行代码：src/distill.rs（SoftTargets 软标签 + kd_loss + distill_loss；单测跑 cargo test distill，数量以实际输出为准） distill 子命令——温度/top-k 对软标签的影响、KD 梯度的解析反向 vs 有限差分自检、 「软标签 vs 硬标签」同一学生同数据对照。

与前几课的衔接：监督信号从第 14 课的硬标签（one-hot）升级为 teacher 的完整概率分布； 损失仍是第 6 课的交叉熵（硬标签项），KD 项是 softmax 之间的 KL 散度； distill_loss 的组合方式（两棵子树按 α 加权相加）用的是第 2 课自动微分的多路反传。

1. 本课要搞懂的问题

  1. 硬标签（one-hot）丢掉了什么信息？为什么这些信息值钱？
  2. 温度 T 到底在调什么？为什么 KD 损失里必须乘 T²？
  3. top-k 截断为什么既省算力又不掉点？
  4. 怎么用数值手段证明 KD 的反向写对了（而不是"loss 在下降就算对"）？

2. 硬标签丢了什么

预训练与 SFT 用的都是硬标签：序列里下一个位置恰好是哪个 token，其它 token 概率一律算 0。

"the cat sat on the ___"   →  硬标签:  mat = 1.0，其余 50000 个 token 全 0

可真实分布并不是 one-hot：mat 与 floor 都讲得通，只是前者更可能。硬标签把这层 "错的那个有多接近"抹平了，模型只学到哪个是对的，学不到类间相似度。

Hinton 等 2015 那篇蒸馏论文把这部分信息叫 dark knowledge（暗知识）：真正值钱的不是 teacher 在正确答案上的那个大概率，而是非目标类上那些小概率——它们编码了 teacher 见过的所有"相似的错误"。

teacher 的真实分布（温度 T = 1）：
  e  0.511 ｜ a  0.153 ｜ .  0.128 ｜ o  0.088 ｜ ,  0.045 ｜ ...

（上表是 cargo run --release -- distill 的实测：正确 token 是 h，teacher 自己也只有 0.5 的把握，剩下的大概率分给了另外几个元音与标点——这条"元音之间相似性"的线索是 硬标签里拿不到的。）

3. 软标签：温度缩放

把 teacher 的 logits 除以温度 T 再 softmax，就得到软标签：

$$ p_t{(j)} = \frac{\exp(z_t{(j)} / T)}{\sum_k \exp(z_t^{(k)} / T)} $$

  • T = 1：teacher 自己的分布。
  • T > 1：分布变平，"负类上的小概率"被放大，类间结构更明显——但也别太大， T → ∞ 时分布趋于均匀，等于在教噪声。实践中 T ∈ [2, 8]（Hinton 原文用 4）。

实测同一窗口（词表 38 类）的平均熵：

温度 平均熵 满词表均匀分布的熵
T = 1.0 1.262 3.638
T = 4.0 3.386 3.638

温度 4 把熵从 1.26 抬到 3.39——离"均匀分布"这个上界（3.64）已经很近，说明 尾部那些小概率真的被抬起来了，学生才有东西可学。

4. T² 缩放：不能省的那一项

蒸馏损失里 KD 项要乘 T²：

$$ \mathcal{L} = (1-\alpha)\cdot \text{CE}(z_s, y) + \alpha \cdot T^2 \cdot \mathrm{KL}(p_t ,|, p_s) $$

为什么：温度把 logits 除以 T，对 z_s 求导会多出一个 1/T：

$$ \frac{\partial \mathrm{KL}}{\partial z_{s,j}} = \frac{1}{T}\left(p_{s,j} - p_{t,j}\right) $$

乘上 T² 之后，KD 项对学生 logits 的梯度变成 (T)·(p_s − p_t)，与硬标签项的 量级可比。少了 T²，高温下 KD 的梯度会比硬标签小 T 倍，α 就失去了意义 （你以为软硬各占一半，实际上软标签那一半被静默地削弱了）。

本模块把 T² 内置在 kd_loss 里，调用方不要再乘一次。

5. top-k 截断：既省算力又去噪

SoftTargets::from_logits 支持只保留 teacher 分布的 top-k 个类别，其余置 0 并重新归一化。

两个好处：

  1. 省算力：反向只需遍历被保留的列（[rows, vocab] → [rows, k]）。
  2. 去噪：温度放大后，词表尾部几万个极小概率被一起放大，它们在 teacher 那里 本来也只是噪声。k 取 8~64 是常见区间，0 = 不截断。

实现上不是全排序，而是 select_nth_unstable_by(k-1)（O(vocab) 的部分选择）：

order.select_nth_unstable_by(k - 1, cmp); // 第 k 大的落到 k-1 位，前面恰好是最大的 k 个
order.truncate(k);
order.sort_unstable_by(cmp);              // 只对这 k 个排序

并列时的排序规则是"logits 降序，并列按下标升序"——确定性是复现实验的前提， 否则同一份数据两次运行可能选出不同的 top-k 集合。

6. KD 的反向：解析式推导与数值核对

前向是"两趟 softmax + 逐行 KL"，反向可以手写成一行：

$$ \frac{\partial \mathcal{L}}{\partial z_{s,j}} = \frac{T^2}{N_{\text{valid}}} \cdot \frac{1}{T}\left(p_{s,j} - p_{t,j}\right) = \frac{T}{N_{\text{valid}}}\left(p_{s,j} - p_{t,j}\right) $$

这式子的好处是不需要保存 [rows, vocab] 的中间量，反向按需重算 softmax 即可。 代价是 softmax 要算两遍（前向一遍、反向一遍），换的是显存。

cargo run --release -- distill 第二节做的是有限差分核对：对 [rows, vocab] 的 每个元素，用 (L(z+ε) − L(z−ε)) / 2ε 逼近数值梯度，与解析反向逐元素比：

核对 608 个元素，最大误差 3.85e-4（loss = 4.683002，T = 4.00 时梯度量级 ~0.250）

为什么这一步必须有：T² 漏乘、或者 (p_s − p_t) 写反（变成把学生推离 teacher 的损失），都不会让 loss 数字看起来异常——loss 照样下降，只是学错了方向。 只有数值核对能发现。

7. 对照实验：同一学生、同一批数据，只差一个 α

distill 子命令第三节把教师训好（教师 200 步：CE 3.6758 → 1.0173）， 再用同一个学生、同一批数据、同一步数跑两组：

配置 验证 CE 困惑度 对教师的 KL top-1 一致率
只对硬标签（α = 0） 5.5922 268.314 0.3023 22.7%
硬标签 + 蒸馏（α = 0.50） 3.9682 52.889 0.1572 32.8%

学生参数量只有教师的 22.6%，自己从数据里能学到的就那么多。软标签是额外的监督： 同一句话，学生得到的不再是 one-hot，而是一整套类间相似度。所以它同时改善了两者：

  • 更贴近教师：KL 从 0.30 降到 0.16，top-1 一致率从 22.7% 升到 32.8%；
  • 在真实标签上的 CE 也更低（5.59 → 3.97）——因为"温柔的目标"本身是一种正则， 抑制了模型在 one-hot 目标下的过拟合。

9. 运行与验证

本课的实测都在 distill 子命令的三节演示里（cargo run --release -- distill：软标签分布 → 有限差分核对 → 只差一个 α 的对照实验），单测跑 cargo test distill。

常见坑（实测踩出来的）

1. T² 不能省（见第 4 节）

本模块内置，调用方不要再乘。

2. teacher 与 student 必须共用同一个分词器

软标签是"词表上的一条概率向量"， 两个模型只要有一个 id→token 映射不同，第 j 维就不再指同一个 token，蒸馏等于在 教学生错误的对应关系。代码用 vocab 相等做断言，但同词表大小 ≠ 同映射， 真正的保证是两者用同一个 tokenizer.json。

3. teacher 必须在 no_grad 下前向

教师只提供标签，不该被更新，也不该占显存存图。

10. 小结与下一课

本课小结

知识蒸馏把训练信号从 one-hot 硬标签换成 teacher 的完整分布：温度 T 放大暗知识、T² 保持梯度量级、top-k 截断省算力又去噪；同一学生、同一批数据只改 α，验证 CE 从 5.5922 降到 3.9682。

拓展方向

  • 特征蒸馏：不止蒸馏最后一层 logits，还把中间层的隐状态（或注意力图）对齐—— FitNets / TinyBERT 走这条路。
  • 在线蒸馏：teacher 与 student 同时训练、互为对方更新（Deep Mutual Learning）。
  • 自蒸馏：teacher 就是自己上一轮的快照，用不着额外的模型（Born-Again Networks）。
  • RLHF 里的蒸馏：把 DPO 对齐后的大模型蒸馏回小模型（见第 36 课）。
  • 接真数据：本课用内置小语料跑通链路；换成真实 teacher checkpoint（--ckpt） 与真实语料，就是工业界缩模型的标准做法。
